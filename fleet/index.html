Runs the gallery's programs on this device, one at a time, and reports what each did: whether its ! ran on the GPU, whether the result is right, how long the shader took to compile and how fast it runs. A report from a GPU we have never held is how the compiler learns it.

Nothing is sent anywhere: the report stays on this page until you copy it. Keep this tab in front while it runs (a hidden tab is slowed down, and its numbers mean nothing). The first run compiles every shader, which on Windows takes a minute or two a program; a second run reads them from the browser's cache. Every loop of a shader counts its turns, so no dispatch can hold the GPU.

The rows named profiled say where a frame's time goes: sending, the GPU's rounds, reading back. With ts they time each kernel on the GPU, which slows them: that fps is not the program's. The last six run the same programs with their run in one kernel where the rows above split it in several (on a Mac both are one kernel). One kernel runs faster and compiles slower, and on some drivers its compile ends the browser's GPU process: the rows after it then run on the cores, and WebGPU comes back when the browser restarts. That too is a result worth the report.
